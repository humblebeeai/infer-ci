# 얼굴 인식 출결 (ChokePoint)

## 문제

문에 설치된 얼굴 인식 카메라가 누가 언제 들어왔는지 기록합니다. 이 기록이 얼마나
자주 맞을까요? 그리고 작은 테스트만으로 얼마나 확신할 수 있을까요? 이 예제는
[ChokePoint 데이터셋](https://zenodo.org/records/815657)으로 이를 측정하고,
`infer-ci`로 모든 지표에 95% 신뢰구간을 붙입니다.

## 실험 구성

- **등록:** 1번 출입구(`P1E_S1`, 카메라 C1)의 25명입니다. 2번 출입구에만 나오는
  4명(0002, 0028, 0029, 0030)은 등록하지 않았습니다.
- **테스트:** 2번 출입구 `P2E_S1` 시퀀스, 카메라 C3의 두 촬영일입니다
  (`P2E_S1.1` 등록자 21명, `P2E_S1.2` 등록자 4명).
- **예측:** 모든 프레임에 InsightFace `buffalo_l`을 실행했습니다(검출된 얼굴 2,247개).
- **기록:** 프레임마다 가장 큰 얼굴만 사용합니다. 한 사람에 대해 `best_score ≥ 0.5`인
  6번째 프레임의 시간에 그 사람을 기록합니다.
- **정답:** 각 사람이 처음 보이는 프레임의 시간입니다(프레임 / 30초).
- **비교** (같은 세션·카메라, 허용 오차 1초): match, late, early, missed, extra.
  미등록자는 세지 않습니다. 기록되지 않는 것이 정상이고, 미등록자 ID로 기록이
  생기면 extra로 셉니다.

코드와 실행 방법은 `notebooks/chokepoint/`에 있습니다(`README.md` 참고).

## 결과

등록자 25명 모두 제시간에 기록되었습니다: match 25, late·early·missed·extra 0.

| 지표 | 값 | 95% 신뢰구간 |
|---|---|---|
| 정확도 | 1.000 | [0.867, 1.000] |
| late/early 비율 | 0.000 | [0.000, 0.133] |
| missed 비율 | 0.000 | [0.000, 0.133] |
| extra 비율 | 0.000 | [0.000, 0.133] |
| Precision | 1.000 | [0.867, 1.000] |
| Recall | 1.000 | [0.867, 1.000] |
| F1 | 1.000 | [1.000, 1.000] |
| 시간 오차 MAE(초) | 0.132 | [0.107, 0.191] |
| 평균 차이(초) | 0.068 | [−0.025, 0.105] |
| 시간 차이 절댓값 p95(초) | 0.233 | [0.133, 0.500] |

비율과 Precision/Recall은 Wilson 구간, F1은 델타 방법, 시간 지표는 부트스트랩
구간입니다.

**설정 비교.** 허용 오차 1초에서 threshold 0.3–0.5는 k 1–10 모두 전원을 기록합니다.
threshold 0.55부터는 일부를 놓칩니다(정확도 0.92–0.96). threshold 0.5, k 6이면
허용 오차 0.5–5초 모두에서 25명 전원이 match입니다. 어떤 설정에서도 extra 기록은
없었습니다.

## 신뢰구간이 알려 주는 것

- 모든 점추정값이 완벽하지만, 테스트는 25번의 통과뿐입니다. 정확도 구간
  [0.867, 1.000]은 실제 정확도가 약 87%까지 낮을 수 있다는 뜻입니다.
- 촬영일 하나만 보면 구간이 더 넓습니다. `P2E_S1.2`는 4명이라 정확도 구간이
  [0.510, 1.000]입니다. 오류가 없더라도 작은 테스트로는 시스템이 믿을 만하다고
  말할 수 없습니다.
- F1 구간 [1.000, 1.000]의 폭이 0인 것은 오류가 없으면 델타 방법의 분산이 0이
  되기 때문입니다. Precision, Recall 구간과 함께 읽어야 합니다.
- 기록은 정답과 0.5초 이내이고, 95%는 약 0.23초 이내입니다. 시간 지표의 구간이
  좁아서 이 카메라에서는 허용 오차 1초가 충분합니다.
- 구간을 좁히려면 더 많은 시퀀스와 카메라로 평가해야 합니다.
